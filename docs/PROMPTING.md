# 대회용 Claude Code 프롬프트 가이드 — 크레딧 적게, 결과는 빠르게

## 0. 핵심 원리 (이것만 기억)
Claude Code는 **매 메시지마다 지금까지의 대화 전체 + CLAUDE.md + 읽은 파일 내용**을 다시 처리합니다.
그래서 크레딧은 "질문을 몇 번 했나"보다 **"대화가 얼마나 길어졌나"**에 비례해 늘어납니다.

| 크레딧이 새는 곳 | 해결책 |
|---|---|
| 한 세션에서 여러 기능을 계속 이어감 | **이슈 하나 = 세션 하나.** PR 올리면 `/clear` |
| "알아서 찾아봐" → 레포 전체 탐색 | 파일 경로를 `@app/src/...`로 직접 지정 |
| 모호한 요청 → 엉뚱한 구현 → 재작업 | 아래 템플릿의 **완료 조건**을 반드시 적기 |
| 실패 → 수정 → 실패 무한 루프 | CLAUDE.md에 "2회 실패 시 멈춤" 규칙(이미 들어 있음) |
| 긴 로그·에러 전체 붙여넣기 | 에러 메시지 + 관련 20~30줄만 |
| 매 라운드 모든 문서 재독 | `/catchup`이 **바뀐 문서만** 읽도록 되어 있음 |
| 장황한 설명 출력 | "요약 3줄" 규칙(이미 들어 있음) |
| 쉬운 일에 비싼 모델 | 계획·리뷰·디버깅은 상위 모델, 단순 반복 구현은 `/model`로 가벼운 모델 |

## 1. 슬래시 커맨드 (자주 쓰는 프롬프트를 고정 → 매번 길게 쓸 필요 없음)

| 언제 | 누가 | 입력 |
|---|---|---|
| 주제 발표 직후 1회 | PM | `/kickoff <주제 원문 붙여넣기>` |
| 매 라운드 시작 | 전원 | `/catchup` |
| 특정 이슈 작업 | 전원 | `/task 12` 또는 `/task 12 지도는 카카오맵으로` |
| 특정 PR 리뷰 | 전원 | `/review 34` |

> `/catchup`은 GitHub 아이디를 `@me`로 자동 인식하므로 각자 파일을 고칠 필요가 없습니다.

## 2. 즉석 요청 템플릿 (커맨드로 안 되는 일)
```
[목표] 한 문장
[범위] @app/src/pages/Home.tsx @server/routes/feed.py  (이 밖은 건드리지 마)
[완료 조건] - 피드에 최신순 10개 표시  - 빈 목록이면 안내 문구
[검증] npm test -- Home
```
`[출력]`은 CLAUDE.md가 이미 3줄 요약으로 정해두었으니 생략해도 됩니다.

❌ 나쁜 예: "홈 화면 좀 예쁘게 하고 피드도 붙여줘"
✅ 좋은 예: 위 템플릿 — 범위가 좁고, 끝났는지 판단할 기준이 있음

## 3. 버그 요청 템플릿
```
[증상] 로그인 후 피드가 빈 화면
[재현] 1) 앱 실행 2) test 계정 로그인
[에러] TypeError: Cannot read 'items' of undefined (Feed.tsx:42)
[의심] 서버 응답 필드명이 data.items가 아니라 data.posts일 수도
```
"의심"을 한 줄만 적어도 탐색 범위가 확 줄어듭니다.

## 4. 세션 운영 습관
- PR 올렸으면 → `/clear` 후 다음 이슈
- 대화가 길어졌는데 이어서 해야 하면 → `/compact` (요약 후 계속)
- 큰 작업은 계획 먼저 → Claude Code의 plan mode(Shift+Tab)로 계획만 받고, 승인 후 구현
- 같은 질문을 두 세션에서 하지 않기 — 결정은 `docs/planning.md` 결정 기록에 한 줄

## 5. 대회 타임라인
**대회 전 (지금 할 수 있는 것)**
- [ ] CODEOWNERS·CONTRIBUTING·README·planning의 `TEAMMATE_B/C`를 실제 GitHub 아이디로 교체
- [ ] 라벨 생성 (`feature`, `bug`, `docs`)
- [ ] 팀원 전원 `gh auth login` + Claude Code에서 `/catchup` 한 번 돌려 동작 확인
- [ ] 쓸 스택 1~2개 정해두고, 빈 프로젝트가 뜨는지 미리 확인 (설치 시간 절약)

**T0 (주제 발표)**: PM `/kickoff` → 아이디어 고르기 → 이슈 생성 → 골격 PR 병합
**본 개발**: 각자 `/catchup` 또는 `/task N` → PR → `/clear` 반복
**마감 2시간 전**: 기능 동결. 버그 수정만.
**마감 1시간 전**: 데모 시나리오대로 리허설, 발표 자료
