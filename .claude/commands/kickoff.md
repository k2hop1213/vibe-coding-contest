대회 정보:
$ARGUMENTS

참고할 파일은 `CLAUDE.md`, `docs/planning.md`, `CONTRIBUTING.md`의 7장(담당자 표)뿐이다. 그 외는 열지 마라.
각 단계 끝에서 **멈추고 내 답을 기다려라.**

1. **아이디어**: 제한시간 안에 3명이 데모 가능한 아이디어 3개. 각각 2줄(무엇을 / 심사기준에서 왜 이기는지) + 난이도(상/중/하). 추천 하나 표시. → 멈춤.
2. **범위 확정**: 고른 아이디어로 `docs/planning.md`를 채워라. MVP는 3~5개, "하지 않는 것"을 반드시 적고, 데모 시나리오와 API 계약(필드명·상태코드까지)을 구체적으로. 스택은 팀이 아는 것 중 가장 빠른 것으로 제안. → 변경 요약만 보여주고 멈춤.
3. **이슈 초안**: 트랙별 이슈 목록을 표로(제목 / 담당 / 선행 이슈 / 예상 시간). 한 이슈 = 한 PR = 1~2시간 크기. 서로 막히지 않게 API 계약·골격 이슈를 맨 앞에. → 멈춤.
4. **이슈 생성**: OK 받으면 `gh issue create`로 생성. 본문은 `.github/ISSUE_TEMPLATE/feature.md` 형식, `--assignee`, `--label feature`. 생성된 번호를 `docs/planning.md` 역할 분담 표에 반영.
5. **골격**: `chore/init-skeleton` 브랜치에서 최소 실행 골격(앱·서버가 뜨고 헬스체크 하나 통과)만 만들고, `CLAUDE.md`의 프로젝트 섹션(스택·실행·테스트·린트 명령), `README.md` 폴더 구조, `ci.yml`의 echo 줄을 실제 명령으로 교체. 로컬 실행 확인 후 PR.
6. 요약 3줄.
